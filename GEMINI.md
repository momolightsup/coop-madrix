# Project Operating Rules & Safety Guidelines

These rules apply unconditionally to all operations, commands, and code implementations in this project (`Coop Madrix`).

---

### Rule 1: Safety & System Integrity Check
- **Pre-execution Verification**: Before executing any prompt, command, or script, always verify that it will not cause any harm, system instability, or damage to the computer, operating system, or existing files.
- **Safe Execution Only**: Never execute untrusted or destructive shell commands, system configuration changes, or actions that could affect areas outside the project workspace.

### Rule 2: Strict File Retention & Storage Scope
- **No File Deletions**: Under no circumstances should files be deleted. If a file is deprecated or obsolete, retain it or discuss non-destructive alternatives (e.g., archiving) only with explicit permission.
- **Dedicated Project Folder Storage**: All code, configurations, data, generated assets, documentation, and dependencies must be stored strictly within the project directory (`c:\Users\monik\OneDrive\Dokumente\Projects\Coop Madrix`). Never store project data outside this directory.

### Rule 3: Planning & Explicit Permission
- **Plan Proposal**: Before executing any significant programming work, feature implementation, refactoring, or architectural setup, propose a detailed, structured plan.
- **Approval Gate**: Do not begin implementation until explicit permission and approval are granted by the user.

### Rule 4: Time & Effort Estimation
- **Time Estimates**: In every proposed plan, include an estimated timeframe / duration (e.g., in minutes or hours) for how long the task is expected to take, along with a breakdown of effort across key milestones.
